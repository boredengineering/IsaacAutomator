# Session Memory: Implementation of Dynamic Component Manifest Engine & Strict Autonomous Git Commit Prevention

## Summary
Successfully implemented the Dynamic Component Manifest Engine per `.agents/references/plans/dynamic-component-manifest-engine-plan.md`, eliminating static, hardcoded component enumeration across Isaac Automator. Users can now declare arbitrary Git repositories, tools, and benchmarks in their workstation profiles without modifying the codebase. In addition, established strict rules preventing autonomous agent git commits.

## Decisions & Rationale
1. **Universal Parameterized Role (`roles/workspace-component`)**: Replaced dedicated single-tool roles with a single parameterized role executing over `profile_components`. Leverages `roles/public-git/tasks/source.yml` for hardened HTTPS-only cloning and hooks neutralization.
2. **Kahn's Topological Dependency Ordering (`ComponentDAGResolver`)**: Components declare `dependencies: [...]`, and the parser sorts them into strict installation DAG order while detecting and rejecting cycles.
3. **Dynamic Coverage Mapping in `profile_adapters.py`**: Avoided hardcoded component tuples (`(('sim', 'isaacsim'), ...)`) by dynamically iterating over open-world components, resolving destinations under named/flat workspaces or explicit `install_dir`, and satisfying the leaf coverage compiler (`mark`, `subtree`).
4. **Clean Transport & Inventory Serialization**: Emitted `profile_components` and `profile_components_json` to `[isaac_workstation:vars]` while preserving the Click argument boundary (preventing unknown option errors for open-world components).
5. **Dynamic State Ledger Convergence**: Refactored `roles/state-ledger/tasks/main.yml` to loop dynamically over `profile_components`, verifying commit hashes and recording them into `state.json`.
6. **Strict Autonomous Git Commit Rule**: Enforced explicit user permission prior to any git commits in `.agents/rules/git-workflow.md` and root `AGENTS.md`.

## Discovered Gotchas & Caveats
1. **Local Adapter Schema Flattening**: `isaac-installer/lib/core/profile_parser.py` flattens local YAML artifacts into scalar environment variables (`CFG_*`). Therefore, `profile_components` (which is a list of dictionaries) is scoped exclusively to `adapter == 'ansible'`.
2. **Deployer Resolved Intent Precedence**: In `deployer.py`, `software_profile_report()` must prioritize `self.params.get('software_profile')` (which contains the post-callback resolved dictionary) rather than re-reading the raw un-resolved file path from `self.input_params`.
3. **Ansible `include_tasks` Dictionary Syntax**: When using `apply` in `ansible.builtin.include_tasks`, shorthand syntax conflicts with action statements. Use dictionary syntax (`file: component.yml`, `apply: tags: [...]`).
