# Session Memory: Auto-Resume Stopped Workstation, Profile Provenance Layering & Live RoboLab Convergence

## Summary
Resolved operational friction for entry-level operators and completed the dynamic deployment of `RoboLab` onto the live GCP workstation (`studio-workstation`). Implemented automatic state detection and auto-resume for stopped (`TERMINATED`) VMs during Ansible update runs, layered human- and machine-readable profile provenance across `.inventory` and runtime Ansible tasks, fixed CLI profile persistence when restoring deployment state, converged `RoboLab` via Ansible with 0 errors (`ok=274`), and cleaned up legacy directory drift on the remote machine.

## Key Changes & Discoveries

### 1. Auto-Resume for Stopped VMs (`Deployer.ensure_workstation_running`)
- Entry-level operators updating their configurations (e.g. `./deploy-gcp ... --existing run_ansible`) previously faced SSH timeout failures if the target VM was stopped in the cloud console.
- Added `ensure_workstation_running()` to `src/python/deployer.py` and `deploy-gcp`:
  - Queries instance status via `gcp_get_instance_status` / `aws_get_instance_status`.
  - If `TERMINATED` or `stopped`, prints an auto-resume banner and invokes `gcp_start_instance` / `aws_start_instance`.
  - Polls until the VM transitions to `RUNNING` before attempting connection or inventory provisioning.
  - Skips execution cleanly during `--dry-run`.

### 2. Multi-Layered Profile Provenance & Transparency
- Addressed operator visibility into which profiles generated the deployment:
  - **Inventory Header**: Injected a top-of-file banner into `.inventory`:
    ```ini
    # ==============================================================================
    # Workstation Deployment: studio-workstation (Cloud: gcp)
    # Security Profile: enterprise (configs/profiles/studio-enterprise.yaml)
    # Software Profile: boredengineering-dev (configs/workstations/boredengineering-dev.yaml)
    # ==============================================================================
    ```
  - **Ansible Inventory Variables**: Emitted `profile_name`, `security_profile_name`, `security_profile_source`, `software_profile_source`, and `profile_components` directly into `[isaac_workstation:vars]`.
  - **Real-Time Display Pre-Task**: Added a pre-task to `src/ansible/isaac-workstation.yaml` to log profile provenance to stdout immediately upon playbook execution.

### 3. Preserving Profile Intent Across State Restorations
- Discovered that when running with `--existing run_ansible` or `repair`, `Deployer.main()` restored `params` from `meta.json`, which overwrote `self.params['software_profile']` with the stale snapshot from initial provisioning.
- Patched `src/python/deployer.py` to preserve explicit CLI profile intent and re-resolve software profile files from disk when present.

### 4. Live RoboLab Convergence
- Executed live run:
  ```bash
  ./deploy-gcp studio-workstation \
    --zone us-central1-b \
    --profile configs/profiles/studio-enterprise.yaml \
    --project cybernetic-renan \
    --ingress-cidrs auto \
    --existing run_ansible
  ```
- **Auto-resumed** VM from `TERMINATED` to `RUNNING`.
- Successfully cloned and installed `RoboLab` into the `isaaclab` conda environment (`/usr/local/bin/isaaclab-env pip install -e .`), deployed desktop launcher, and registered commit `b6cfcf6ccd2113c4cd1216d35b33024a7d5691da` into `/home/ubuntu/.isaac-state.json`.

### 5. Casing Drift Resolution & Remote Cleanup
- Identified why `/home/ubuntu/Documents/GitHub/boredengineering` appeared on the workstation: during the initial run before profile persistence was fixed, the legacy `roles/robolab/defaults/main.yml` fallback was used, which had hardcoded lowercase `robolab_org: boredengineering`.
- Updated `src/ansible/roles/robolab/defaults/main.yml` to default `robolab_org: BoredEngineer` and `robolab_git_checkpoint: "no"`.
- Cleaned up the orphaned `/home/ubuntu/Documents/GitHub/boredengineering` directory via remote SSH execution, leaving only the authoritative `/home/ubuntu/Documents/GitHub/BoredEngineer` tree.
