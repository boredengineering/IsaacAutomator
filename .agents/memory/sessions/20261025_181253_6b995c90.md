# Session Memory: Cloud Profile Reconciliation with Full Physical AI Ecosystem

## Summary
Reconciled the local host bare-metal physical AI workstation stack (`isaac-installer/config/full-ecosystem.yaml`) with the cloud deployment specifications (`configs/profiles/studio-enterprise.yaml`). Created the declarative workstation software contract `configs/workstations/cloud-ecosystem.yaml` that renders with 100% coverage and 0 blockers/warnings across both `ansible` (cloud deployment) and `local` (bare-metal execution) adapters. Enhanced `DeployCommand.parse_args` to discover software profiles and hardware workstation options directly from profile specifications, enabling seamless non-interactive cloud deployments on GCP Flex-start RTX PRO 6000 Blackwell workstations over private Cloud IAP networks.

## Decisions & Rationale
1. **Unified Workstation Profile Contract (`cloud-ecosystem.yaml`)**:
   - Bridges the active physical AI stack: Isaac Sim 6.0.1 (Standalone Kit), Isaac Lab v3.0.0-beta2, IsaacLab-Arena release/0.3.0-prerelease, LeRobot v0.4.3 (isolated env), and Isaac-GR00T dev at reviewed commit `51d4c89f72fda44cbf77285c6a8114b52676b8a1` with ZeroMQ loopback inference on port 5561 with `NEW_EMBODIMENT`.
   - Incorporates the explicit standalone archive URL and verified SHA256 checksum (`613e30d9727baa5615e087148ce67c90d9e5ffa376f7cbb4f01580baeb1c8d13`) for Isaac Sim 6.0.1, satisfying Ansible adapter fail-closed immutability requirements.
   - Pinned target runtime: Conda `isaaclab`, Python 3.12, PyTorch `2.10.0+cu128`, CUDA `12.8`, Architecture `sm_120` (NVIDIA RTX PRO 6000 Blackwell Workstation Edition).

2. **Cloud Profile Optimization (`studio-enterprise.yaml`)**:
   - Adopted `configs/workstations/cloud-ecosystem.yaml` as the authoritative `workstation.software_profile`.
   - Updated remote desktop streaming from `dcv,nomachine` to `nomachine,novnc`. NICE DCV UDP traffic is dropped by Cloud IAP TCP tunneling, whereas NoMachine (TCP 4000) and noVNC (TCP 8080) tunnel reliably over Cloud IAP loopbacks.
   - Preserved `flex_start` scheduling (GCP Dynamic Workload Scheduler with 7-day max runtime) on `g4-standard-48` and private networking (`iap_only: true`, `cloud_nat: true`).
   - Aligned state backend to `local` (`state_bucket: ""`, `state_locking: false`) in accordance with repository safety invariants preventing unmigrated remote state execution.

3. **DeployCommand Non-Interactive Discovery**:
   - Enhanced `DeployCommand.parse_args` in `src/python/deploy_command.py` to inspect the `--profile` configuration file and automatically populate `software_profile`, `instance_type`, `gpu_count`, `remote_desktop`, and IAP ingress CIDRs when omitted from the CLI, eliminating interactive Click prompts during automated deployments.

4. **Comprehensive Example and Fork Profiles (`configs/workstations/`)**:
   - Created `configs/workstations/example-workstation.yaml`: A fully documented example displaying all schema options (5 components, standalone/git modes, 4 runtimes, loopback serving, named/flat workspace, notes).
   - Created `configs/workstations/boredengineering-dev.yaml`: A specialized setup matching the host machine development environment with personal forks under `https://github.com/boredengineering/<repo>` on branch `dev/0.3.0-prerelease` (for Arena, Lab, GR00T, LeRobot) tracking canonical upstream `isaac-sim` and `NVIDIA` remotes with dual-remote tracking metadata in `repositories:`.
   - Updated `src/python/gr00t_serving.py` to allow the verified `boredengineering/Isaac-GR00T.git` fork at reviewed commit `51d4c89f72fda44cbf77285c6a8114b52676b8a1`.

   - Verified zero regressions across the entire test suite (`deploy_command`, `profile_adapters`, `workstation_connection`, `novnc_iap`, `gcp_flex_start`, `gr00t_serving`, `terraform_tui`, `isaac9s`).
