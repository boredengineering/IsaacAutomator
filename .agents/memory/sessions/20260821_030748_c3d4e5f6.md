# Session Memory: In-Depth Architectural Analysis of setup_conda_env.sh vs setup_python_env.sh & Robust Bridge Implementation

## Summary
In this session, we analyzed the critical differences between `setup_conda_env.sh` and `setup_python_env.sh`:
1. **Critical Difference**:
   - `setup_python_env.sh` puts Omniverse Kit's internal Python standard library (`$SCRIPT_DIR/kit/python/lib/python3.12`) on `PYTHONPATH`. If naively symlinked, Kit's bundled stdlib shadows Conda's native standard library, triggering symbol and module collisions.
   - `setup_conda_env.sh` sources `setup_python_env.sh` to obtain Omniverse extensions and Carbonite paths, and then **filters out** Kit's bundled standard library from `PYTHONPATH`.
2. **Code Implementation**:
   - Implemented `deploy_isaacsim_conda_bridge` in `lib/modules/isaacsim.sh`, `lib/modules/isaaclab.sh`, and `lib/core/state.sh` to dynamically write the pure filtering bridge script into `${sim_dir}/setup_conda_env.sh`.
