# Session Memory: Open-Ended Development Architecture Overhaul & Privilege Boundary Decoupling

## Summary
In this session, we overhauled `isaac-install-plan.md` to transition from a naive monolithic provisioning script into a realistic, modular architecture for open-ended robotics development and research.

## Decisions & Rationale
1. **Two-Phase Privilege Boundary**:
   - Split system-level infrastructure (drivers, udev rules, Vulkan, build tools, NVMe mounting requiring `sudo`) from developer workspace setup (Conda/UV environments, git forks, editable pip packages running strictly as the unprivileged user).
2. **Environment Shim Pattern (`isaaclab-env`)**:
   - Replaced global `setup_conda_env.sh` sourcing (which causes ABI collisions and poisons `PYTHONPATH` for non-Isaac projects) with scoped execution wrappers and project virtualenvs.
3. **Topological Extension Resolution**:
   - Enforced explicit installation order: `omni.isaac.lab` -> `assets` -> `tasks` -> `rl` -> RL backends -> Downstream benchmarks/LeRobot with intermediate verification checkpoints.
4. **Teleoperation Latency Hardening**:
   - Codified 1ms FTDI serial latency timer rule (`99-ftdi-latency.rules`) to eliminate 16ms control loop jitter for ALOHA/SO-100 arms.

## Discovered Gotchas & Caveats
- Running `isaaclab.sh --install` under `sudo` causes permission locks in `~/.cache` and Python runtime directories.
- Isaac Sim's bundled libraries can conflict with external PyTorch/CUDA wheels if not scoped properly.
