# Session Memory: Milestone: 100% Workstation Verification Passed & Arena/GR00T Architecture Complete

## Summary
Achieved a complete 100% pass rate (12 of 12 subsystems verified green) across the entire bare-metal Isaac Automator workstation test suite (`./bin/isaac-installer test`). Resolved root issues with Astral UV package synchronization against NVIDIA's PyPI index, eliminated Conda `(base)` environment pollution across simulation runners, and registered `IsaacLab-Arena` in non-invasive Python editable mode across both the Conda `isaaclab` environment and Isaac Sim's standalone runtime.

## Decisions & Rationale
1. **Astral UV Timeout & CDN Retry Policy**:
   - `https://pypi.nvidia.com` hosts multi-gigabyte wheels (`tensorrt-cu12`, `tensorrt-cu12-bindings`, `flash-attn`) that frequently drop connections or time out under standard 30s limits.
   - Configured `UV_HTTP_TIMEOUT=300`, `UV_CONCURRENT_DOWNLOADS=2`, `UV_INDEX_STRATEGY=unsafe-best-match`, and automated 3-attempt retry loops in `sync_gr00t_env` and CLI subcommand `./bin/isaac-installer gr00t sync-env`.
2. **Conda `base` Environment Isolation in `run_as_user`**:
   - When interactive user shells have `(base)` active (`~/.bashrc`), `$CONDA_PREFIX` points to `/home/tarfy/miniconda3`. Isaac Lab's `isaaclab.sh` script inspects `$CONDA_PREFIX` and would inadvertently execute base python (lacking PyTorch/Omniverse).
   - Injected runtime sanitization in `detect.sh` (`run_as_user`): if `CONDA_DEFAULT_ENV == 'base'`, it unsets base variables and dynamically points `CONDA_PREFIX` to `/home/tarfy/miniconda3/envs/isaaclab`.
3. **Dual-Runtime Editable Bridge for Arena**:
   - `IsaacLab-Arena` (`isaaclab_arena==0.3.0`) is registered via `pip install -e` in both Isaac Sim bundled python (`_isaac_sim/python.sh`) and Conda `isaaclab` (`isaaclab-env` / `~/miniconda3/envs/isaaclab/bin/pip`).
   - Ensures `import isaaclab_arena` and Gymnasium benchmark tasks resolve with 100% parity across all execution vectors (`conda activate isaaclab`, `isaaclab-env`, and `./isaaclab.sh -p`).

## Discovered Gotchas & Caveats
- **Python Package Naming**: IsaacLab-Arena installs as `isaaclab_arena` in Python site-packages, not `arena`.
- **Isaac Sim Python Wrapper Parsing**: Passing complex multi-line strings to `_isaac_sim/python.sh` via `-c` triggers shell argument splitting. Verification probes must use atomic single-line commands or small script files.
- **Strict Process Separation**: `IsaacLab` (Python 3.12, PyTorch 2.10.0+cu128) and `Isaac-GR00T` (Python 3.10, PyTorch 2.9.0) must never share a single virtual environment; they communicate strictly over decoupled IPC (ZeroMQ REP/REQ sockets).
