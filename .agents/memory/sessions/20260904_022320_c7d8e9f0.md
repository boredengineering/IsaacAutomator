## 1. Summary of Updates

1. **Threat Surface & Codebase Audit**:
   - Audited existing GCP codebase (`src/terraform/gcp/`, `src/python/deployer.py`, and `ovkit/`).
   - Identified critical risks: plaintext private keys in local `.tfstate` and `key.pem`, default Compute Engine SA with overly broad scopes (`devstorage.read_write`), unencrypted boot disks, direct exposure of ingress ports to `0.0.0.0/0`, and lack of distributed state locking.

2. **Core Security Pillars**:
   - **Cloud KMS & CMEK**: Designed regional KMS Key Ring with 3 dedicated CryptoKeys (`tfstate-key`, `compute-disk-key`, `secrets-key`) with 90-day automated rotation and required GCP service agent IAM bindings (`compute-system`, `gs-project-accounts`, `gcp-sa-secretmanager`).
   - **Google Secret Manager**: Codified CMEK-backed secret storage for NGC API keys, HF tokens, WandB keys, and desktop session passwords, with zero-bake instance retrieval via metadata OAuth tokens.
   - **Hardened GCS Remote State**: Designed production GCS backend with Uniform Bucket-Level Access, object versioning, public access prevention enforced, 7-day soft-delete retention, and native Terraform state locking.

3. **Ideal Architecture & Defense-in-Depth ("What Else Would Be Ideal")**:
   - **Zero-Trust Network & IAP**: Private VMs without public external IPs, using Cloud Identity-Aware Proxy (IAP) TCP forwarding (`35.235.240.0/20`) for SSH and remote desktops, Private Google Access (PGA), and Cloud NAT for outbound updates.
   - **Hardware & Boot Integrity**: Shielded VM (`enable_secure_boot`, `enable_vtpm`, `enable_integrity_monitoring`) and CMEK-encrypted boot disks.
   - **Access Control & Central Identity**: OS Login with mandatory 2FA (`enable-oslogin = TRUE`, `block-project-ssh-keys = TRUE`), eliminating fragile static metadata keys.
   - **Modern IAM**: Dedicated `isaac-workstation-sa` following Principle of Least Privilege and Workload Identity Federation (WIF) for keyless CI/CD.
