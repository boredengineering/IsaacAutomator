# Session Memory: Root Cause Resolution: Elimination of /opt/conda Resolution Trap & Dynamic Miniconda3 Discovery

## Summary
In this session, we pinpointed why `/opt/conda/envs/isaaclab` was still appearing and why `repair` reported zero drift:
1. **Root Cause Analysis**:
   - `resolve_conda_env_path` was querying `conda env list --json`, which found `/opt/conda/envs/isaaclab` from an old root install.
   - It accepted `/opt/conda/envs/isaaclab` as the "valid user environment path".
   - The drift audit compared `/opt/conda/envs/isaaclab` against itself, concluded no drift existed, and skipped creating `/home/tarfy/miniconda3/envs/isaaclab`.
   - `~/.conda/environments.txt` also retained stale references to `/opt/conda`.
2. **Fixes Applied**:
   - `lib/modules/conda.sh`: Pinned `resolve_conda_env_path` strictly to `${conda_root}/envs/${env_name}` (`~/miniconda3/envs/isaaclab`) and added `environments.txt` sanitization (`sed -i '\|/opt/conda|d'`).
   - `lib/core/state.sh`: Flagged any `/opt/conda` presence as explicit drift (`CONDA_ENV_MISLOCATED`) and purged it completely.
   - `bin/isaaclab-env`, `auth.sh`, `ecosystem.sh`, `physical_ai.sh`, `audit.sh`: Dynamically resolve user's `miniconda3` path instead of static `/opt/conda`.
