### Priority 1: Runtime identity and environment isolation

- Local default profile pins Sim 6.0.1, Lab v3.0.0-beta2 and Arena release/0.3.0-prerelease (`isaac-installer/config/default-profile.yaml:25-62`). Cloud CLI uses independently resolved `latest` for these components (`src/python/config.py:78-91`, `src/python/deploy_command.py:189-229,267-291`); Packer has explicit pins (`src/packer/gcp/isaac-workstation.pkr.hcl:73-94`). Default paths are not a locked compatibility tuple.
- Local GR00T and cloud role defaults still select `main`, not active-stack `dev`. Cloud native embodiment default is `OXE_DROID_RELATIVE_EEF_RELATIVE_JOINT`, not `NEW_EMBODIMENT` (`src/ansible/roles/gr00t/defaults/main.yml:19-35`). Local native server hardcodes the same old embodiment (`isaac-installer/lib/modules/gr00t.sh:440-447`).
- Cloud Conda role defaults to Python **3.10**, not required 3.12 (`src/ansible/roles/conda/defaults/main.yml:5`). Do not infer the effective deployed interpreter without checking inventory/overrides and actual runtime. Environment task checks existence, not Python version drift (`tasks/main.yml:37-47`).
- Local GR00T uses repo-local UV `.venv`; local LeRobot uses a separate `lerobot` Conda environment (Python 3.10). Cloud native GR00T and LeRobot both install into shared `isaaclab` (`isaac-installer/lib/modules/gr00t.sh:11-84`, `physical_ai.sh:49-108`; `src/ansible/roles/gr00t/tasks/native.yml:67-79`, `roles/lerobot/tasks/main.yml:79-91`). Dependency isolation therefore diverges.
- Local GR00T Blackwell sync skips torch/torchvision and installs cu128, but ignores wheel-install failure (`isaac-installer/lib/modules/gr00t.sh:42-84`). Later plain `uv run` can resynchronize dependencies; server does not use `--no-sync` (`:443`). This is a risk, not an observed runtime rollback in this session.
- Cloud Conda selects torch 2.10.0+cu128 / torchvision 0.25.0+cu128 for compute capability >=12, otherwise torch 2.5.1+cu124 / torchvision 0.20.1+cu124 (`src/ansible/roles/conda/tasks/main.yml:55-63`). Subsequent editable installs do not establish protection against dependency changes.

### Priority 3: Reruns, failures and serving integration

- Cloud Sim/Lab skip Git checkout if build/install marker exists, comparing marker with existing HEAD instead of requested ref (`src/ansible/roles/isaacsim-source/tasks/install.yml:25-50`; `roles/isaaclab-source/tasks/install.yml:25-50`). Changed requested versions may not be applied on rerun.
- Cloud build/install pipelines use `| tee` without pipefail, potentially hiding failure before marker writes (`isaacsim-source/tasks/install.yml:77-92`, `isaaclab-source/tasks/install.yml:100-124`). Local also swallows important failures with `|| true` (`isaac-installer/lib/modules/isaaclab.sh:73-92`). Neither engine's success message is sufficient runtime evidence.
- Local checks are shallow: Lab directory/link/launcher, Arena `.git`, GR00T tools/repo/venv (`isaaclab.sh:11-20`, `isaaclab_arena.sh:11-20`, `gr00t.sh:11-32`). Existing paths do not prove requested versions or installed packages.
- Cloud GR00T native path creates its unit but main tasks do not enable/start it; native handler only reloads systemd. Container branch explicitly starts its service (`src/ansible/roles/gr00t/tasks/main.yml:62-99`, `handlers/main.yml:18-29`). No runtime service status was checked.
