# Session Memory: Workspace Hierarchy, Dual-Remote Forks, and State Drift Self-Healing Engine

## Summary
In this session, we designed and integrated into `isaac-install-plan.md` two major architectural subsystems:
1. **Workspace Hierarchy & GitHub Desktop Alignment**: Declarative layout strategies (`auto`, `org`, `flat`) in YAML to organize repositories under `~/Documents/GitHub/<Owner>/<Repo>` matching GitHub Desktop's user account model.
2. **State Tracking, Drift Reconciliation & Self-Healing Engine (`repair` / `fix`)**: Probing host state, detecting mislocated clones, wrong remotes, branch/tag drift, and broken symlinks, and executing safe automated re-homing, remote re-wiring, and Python package re-indexing.

## Decisions & Rationale
- **Layout Strategy (`workspace.layout`)**:
  - `org`: Nests repositories under `~/Documents/GitHub/<Owner>/<Repo>`.
  - `auto`: Discovers if user folder exists (e.g. `GitHub/BoredEngineer/`) and automatically adopts that structure for new and existing clones.
- **Persistent State Ledger (`~/.isaac-installer/state.json`)**:
  - Tracks active repository paths, remotes, active refs/tags, linked engines, and Python environments to detect and repair drift deterministically.
- **Safe Re-Homing with Dirty Work Protection**:
  - Prevents data loss during migration by checking git status before re-homing directories, creating branch/stash backups if dirty.
