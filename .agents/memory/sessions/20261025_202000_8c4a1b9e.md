## 2. Architectural Design & Implementation

### A. The "Bucket Option" Gate (Strict Opt-In)
- **`bucket: ""` (or `null` / omitted)**:
  - Strict local backend (`state_backend = "local"`).
  - State file resides at `~/.isaac_automator/state/<name>/.tfstate`.
  - Exactly **0 network/CLI calls** to cloud storage APIs (`gcloud storage`, `aws s3api`, `az storage`). Zero cloud storage cost.
- **`bucket: "auto"`**:
  - Deterministically derives `isaac-state-<hash>` from the cloud, namespace, and owner scope.
  - Automatically preflights existence and provisions via `BootstrapSession` if missing.
- **`bucket: "<custom-name>"`**:
  - Targets the named bucket, preflights existence, and auto-provisions if missing.

### B. Ambient Cloud Context Discovery (`src/python/backend_context.py`)
- Automatically discovers without manual prompts or credentials:
  - **GCP**: Project ID from `--project`, `CLOUDSDK_CORE_PROJECT`, or `gcloud config get-value project`; region from `--region` or `--zone` truncation; controller principal from active `gcloud` identity (`user:<email>` or `serviceAccount:<email>`).
  - **AWS**: Account ID from `AWS_ACCOUNT_ID` or `aws sts get-caller-identity`; region from `AWS_REGION` or config; caller ARN.
  - **Azure**: Subscription/tenant and caller identity.

### C. Just-In-Time Bootstrap Engine (`src/python/backend_bootstrap.py`)
- `check_storage_exists(spec, transport=None)`: Read-only absence probe with bounded timeouts.
- `ensure_backend_storage(spec, ...)`: Probes existence. If missing and not `dry_run`, provisions hardened bucket using `src/terraform/bootstrap/<cloud>/main.tf` with uniform access, object versioning, soft-delete retention (7 days), and `prevent_destroy = true`.

### D. Deployer & CLI Integration (`src/python/deployer.py`, `deploy-gcp`)
- `Deployer.ensure_backend_storage()`: Called post-login prior to Terraform initialization.
- Dry-run safety: When `--dry-run` is active, storage creation is strictly suppressed and informative output is logged.
- Teardown isolation: Workstation `./destroy <name> --yes` destroys compute and disks but never deletes the durable state bucket.

## 3. Critic Agent Audit Findings & Fixes
The Critic Subagent (`ffb55785-b604-4d36-b7dd-78f94c74c51a`) executed an adversarial review and remediated 4 issues:
1. **Precedence Corruption**: Removed artificial token injection in `DeployCommand.parse_args` which was overriding profile destinations and causing `NoSuchOption` on non-GCP deployers.
2. **Dry-Run Safety**: Added `dry_run` gating to `ensure_backend_storage` and `deploy-gcp` to prevent live bucket provisioning during `--dry-run`.
3. **Project Scope Isolation**: Disallowed falling back from workload project to remote state backend project.
4. **Scope Regex Enforcement**: Enforced cloud-specific regex patterns on explicit scope inputs in `resolve_ambient_owner_scope`.
