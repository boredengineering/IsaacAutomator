# Session Memory: GCP Flex-start Integration into isaac9s Deploy Modal

## Summary
Integrated first-class GCP Flex-start (Dynamic Workload Scheduler) support into `isaac9s`, bringing complete parity between the CLI (`deploy-gcp --flex-start`) and the in-cockpit deploy modal (`DeployWorkstationModal`).

## Key Changes
1. **Deploy Modal UI & Selection**:
   - Replaced the single Spot checkbox in Section 5 with a `RadioSet` providing 3 mutually exclusive provisioning models:
     - `Standard On-Demand`: Immediate allocation, standard billing.
     - `GCP Flex-start`: Dynamic Workload Scheduler, 7-day max duration, 60m allocation timeout, managed via `./cycle-vm`.
     - `Spot / Preemptible VM`: 60-91% discount, auto-backup & 30s preemption watchdog.
   - Added `update_scheduling_visibility()` to hide the Flex-start option when targeting non-GCP clouds (AWS, Azure, AliCloud) and gracefully fallback to standard.
2. **Zone Mapping & test03 Parity**:
   - Added `us-central1-b (Iowa - RTX Pro 6000 - Flex-start Verified)` to the `g4-` GPU zone catalog in `DeployWorkstationModal.get_zones_for_selection()`.
3. **Dispatch & Telemetry in `app.py`**:
   - Updated `Isaac9sApp.on_deploy_submitted()` to detect `flex_start` and append `--flex-start` when targeting GCP.
   - Added `[FLEX-START DWS]` telemetry badge to the real-time execution logs.
4. **Testing & Verification**:
   - Updated `src/tests/isaac9s.test.py` with Textual pilot assertions verifying Flex-start selection, summary preview text, and modal dismissal.
   - All 87 unit and integration tests passed cleanly.
