## Decisions & Rationale
- **Dynamic Hardware Adaptation**: Probing `nvidia-smi --query-gpu=compute_cap` allows both provisioners to dynamically serve `cu128` wheels (`torch==2.10.0+cu128`) on Blackwell (`sm_120` / `>= 12.0`) while maintaining compatibility with Ada (`sm_89`), Hopper (`sm_90`), and Ampere (`sm_80`) without manual intervention.
- **Astral Lockfile Trap Mitigation**: In `Isaac-GR00T`, upstream `uv.lock` specifies `cu126`. Calling `uv sync --no-install-package torch --no-install-package torchvision` followed by a direct `cu128` wheel install guarantees that re-running installer sync will not downgrade or corrupt a working Blackwell PyTorch installation.
- **Port Conflict Elimination**: Port 5555 frequently collides with VS Code Server internal tunnels. Standardized policy serving on port 5556 (native host standalone) and port 5561 (container daemon), matching Arena configuration.
- **Fresh Machine Pre-emptive Scaffolding**: Host directories (`datasets`, `models`, `eval`, `neo4j`, `huggingface`) are scaffolded under `ansible_user` / host user ownership before any Docker process runs, preventing Docker daemon from creating them as `root:root` with permission denial errors.
- **Experience Memory Orchestration**: Added containerized Neo4j 5.26 service (`neo4j-arena`) on ports 7475 (HTTP) and 7688 (Bolt) with APOC plugins to capture and query simulation autopsies and scene graphs.
