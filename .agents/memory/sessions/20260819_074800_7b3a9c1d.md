# Session Memory: Remote State, DevContainers & Multi-Repo Cloud Dev Architecture

## Summary
Designed comprehensive architectural frameworks for decoupling Isaac Automator workstation state from local machines, enabling multi-machine portability, and supporting local multi-repository development (e.g. `IsaacLab-Arena`, `IsaacGR00T`) against remote cloud GPU compute. Documented the dual-layer VS Code Profile and DevContainer synchronization strategy.

## Decisions & Rationale
- **Dual-Layer VS Code Sync Strategy**:
  - *Layer 1 (Repository Level)*: Hardcode required extensions, linters, and python interpreter paths in `.devcontainer/devcontainer.json` for zero-setup team reproducibility across any machine.
  - *Layer 2 (User Level)*: Use VS Code Settings Sync (GitHub account) or Profile Export (`.code-profile`) for personal UI themes, keybindings, and snippets.
- **Rsync & Mutagen as File Transport Layer**:
  - High-performance local-to-cloud file synchronization (`mutagen` / `fswatch` + `rsync`) mirrors local source directories into `/home/ubuntu/workspaces/` in $<300\text{ms}$.
  - Cloud GPU DevContainers bind-mount `/home/ubuntu/workspaces/` into `/workspaces/` with editable Python installs (`pip install -e .`), allowing live simulation without rebuilding containers.
- **Terraform-Native Remote State Architecture**:
  - Remote Terraform backend (`backend "gcs"` / `backend "s3"` with native `use_lockfile=true`) with bootstrap modules in `src/terraform/bootstrap/`.
  - Zero-downtime state migration for running instances via `terraform init -migrate-state`.
  - Automated private key recovery directly from `terraform output -raw ssh_key`.

## Discovered Gotchas & Caveats
- `DOCKER_HOST=ssh://...` fails with DevContainers due to local vs remote filesystem path mismatches; the standard solution is connecting via **VS Code Remote - SSH** to the cloud VM first, then letting the remote DevContainer extension manage the local Docker daemon.
- When running multiple repositories simultaneously in Isaac Sim, use a **Multi-Root Workspace** (`robotics.code-workspace`) inside a single unified GPU container rather than launching multiple separate 15GB containers.
