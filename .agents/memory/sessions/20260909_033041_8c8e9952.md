## Decisions & Rationale

- `container_registry` optionally selects `gcp_artifact_registry`, `aws_ecr` or
  `dockerhub`. Omission/`enabled: false` leaves source deployment unchanged.
- Existing GCP `artifact_registry` profiles remain supported. Do not author both
  schema blocks. New GCP profiles bridge into existing verified GCP consumers;
  normalized saved forms must agree. AWS ECR requires AWS, GCP requires GCP;
  Docker Hub can be consumed on any supported cloud.
- Registry lifecycle remains separate: protected shared AWS ECR stack with durable
  externally configured S3 backend, explicit access roles and optional KMS key.
  Workstation instance-profile policy allows only specified ECR repository pulls;
  token action needs wildcard IAM resource by AWS design. IMDSv2 required.
- ECR refresh uses official helper behind exact-host allowlist and sanitized
  environment; no static AWS keys. Docker Hub uses isolated anonymous config or
  externally provisioned root Docker auth. No plaintext tokens in YAML/state.
- `huggingface` is independent model/dataset snapshot staging, not OCI image
  hosting. Full commit revisions required; optional target token-file reference;
  isolated client venv and user-owned snapshots. No repository code execution,
  automatic mounts, inference health guarantees or publication pipeline.
- Public examples disabled/generic; private profiles remain ignored and unchanged.

## Discovered Gotchas & Caveats

- Docker Engine strips docker.io/ and optionally library/ in RepoDigests; exact
  equivalent forms now avoid repeat pulls without relaxing namespace/digest checks.
- Fresh `__gr00t`-only generic-container runs lack per-run Docker config facts. They
  now fail before service effects and direct operators to full provisioning or
  `__container_registry,__gr00t`. Cold and repeat combined-tag runs verified.
- Keep first two GR00T fact-resolution tasks before the safety assertion; existing
  GCP tests extract those facts. Assertion still precedes all service operations.
- ECR helper upstream logger falls back to its temp dir: preserve TMPDIR=/dev/null
  together with AWS_ECR_DISABLE_CACHE=true and AWS_ECR_CACHE_DIR=/dev/null.
- Ansible pip itself needs system packaging, not just target venv dependencies.
  HF installs python3-venv + python3-packaging and pins that pip module's interpreter
  to /usr/bin/python3. Enabled regression/mutation checks prove both fixes needed;
  target cache/pip/download steps retain non-root ownership and idempotence.
- Two existing TUI ResourceWarnings remain; prior ignored initializer clean-checkout
  caveat persists. Black/isort/flake8/ansible-lint were unavailable, not passed.
- Live helper/package behavior, IAM propagation, cross-account ECR policy/network,
  real image availability, HF access and GPU runtime acceptance remain unverified.
- HF direct client is pinned; transitive package locking remains a nonblocking
  reproducibility improvement. AWS support covers commercial regional private ECR,
  not China, Public ECR, or government/isolated partitions.
