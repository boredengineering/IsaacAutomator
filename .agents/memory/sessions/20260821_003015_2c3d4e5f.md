# Session Memory: Explanation of Git Fork Tag Isolation and Two-Tier Fallback Clone Strategy

## Summary
In this session, we explained why the initial direct git clone with a tag ref failed and how the installer's two-tier fallback handles it:
1. **GitHub Fork Tag Isolation**: When a GitHub repository is forked (e.g. via `gh repo fork --default-branch-only` or GitHub Web UI), GitHub only creates a copy of the default branch (`main`). Upstream release tags (such as `v3.0.0-beta2`) do not exist on the personal fork yet.
2. **Two-Tier Self-Healing Clone**:
   - Tier 1: Attempts direct clone with desired tag (`git clone -b v3.0.0-beta2 <fork_url>`).
   - Tier 2 (Fallback): Caught `fatal: Remote branch not found`, fell back to cloning `main` from the fork, wired `upstream` to canonical NVIDIA (`isaac-sim/IsaacLab.git`), fetched upstream tags, and checked out `v3.0.0-beta2`.
