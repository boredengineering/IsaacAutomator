## Changes

- `destroy` now fails closed on absent/malformed/ambiguous state, remote intent/descriptors, untrusted paths, failed Terraform operations and incomplete destruction. Validates lineage/serial and remaining managed resources before deleting recovery files.
- `src/python/utils.py` validates local state envelopes/resources, approved paths and metadata; output reads no longer return an empty value for missing/malformed state. Optional missing outputs still return an empty string. Nested controller intent, symlinked ancestors/metadata and nonregular metadata fail closed.
- `terraform_backend.py`: immutable validated BackendSpec, canonical identity and backend field adapters; local/GCS/S3/Azure pairing, secret/unknown-field rejection, v2 namespace mapping, native S3 lockfile and version policy. Local compatibility gate is stable >=1.3.5,<2; conservative remote gate is >=1.10.0,<2. These are feature gates, not proof that every allowed version/provider was exercised.
- `backend_selection.py`, config/Click/Deployer integration: strict bounded YAML/JSON parsing, actual Click source precedence, explicit local overrides for new intent, saved-attachment guards, local built-in team/enterprise defaults and warnings, controller fields excluded from Terraform/Ansible payloads.
- Deployer output and SSH-key export now respect the instance's configured state directory. Restore/mutation paths recheck backend intent.
- `terraform_runner.py`: isolated allowlisted source/data staging, durable absolute local state, controller locking, safe argv/environment, bounded cancellation/timeout, redacted diagnostics, single-use digest-checked plans. Remote apply/destroy remain disabled; production callers are not wired to this runner yet.
- Runner retains private staging when Terraform leaves possible `errored.tfstate`; exposes recovery_directory/recovery_state without publishing contents. Retention is not reboot-durable and needs secure manual review. Ordinary cleanup and controller lock release remain covered.
- `state-backend validate --cloud CLOUD --config PATH [--terraform-version VERSION]`: executable offline validator, container-aware entrypoint, Bash completion and four public examples under `configs/state-backends/`. Success explicitly reports cloud access not checked and remote lifecycle not enabled.
- Host `run` preserves the container command exit code and supports non-TTY execution.
- Cloud entrypoints defer AWS authentication, GCP project discovery and Alibaba region lookup until backend validation. GCP discovery belongs to execution after saved-config handling, not import or constructor; Azure's existing ordering/no-login behavior was tested without changes.
- Updated plan status and profile/backend documentation to distinguish implemented foundations from future operations.
