# Session Memory: C3X OAuth ADC implementation and live catalog verification

## Summary

User asked to add OAuth to C3X and test it. Implemented a standalone patch to
`c3xdev/c3x-pricing-api` pinned at `cc58da98652a0ce9f8aac6d1f574d3578544d8c1`.
The complete patch, reproduction instructions, source hashes, test receipts and
independent review are preserved in `configs/cost/c3x-oauth/`.

The final replayed native probe used existing ADC with API-key variables removed
and quota project `cybernetic-renan`. Actual output was
`{"status":"ok","services":1,"compute_engine_skus":1}`, exit 0. This is a
bounded production-path authentication check, not a full catalog import or quote.

## Decisions & Rationale

- `GCP_AUTH_MODE=adc` explicitly selects refreshable Google OAuth ADC. No gcloud
  subprocess, static bearer-token setting, or automatic API-key fallback.
- Legacy `api_key` remains the default. Optional `GCP_QUOTA_PROJECT` supplies the
  quota header explicitly; it is not inferred from gcloud or credential JSON.
- Importer auth/preflight, safe response handling and standalone opt-in probe were
  added; the existing Isaac Automator/Infracost adapter and isaac9s are unchanged.
- No login, new key, IAM/API configuration change, paid resource, database import,
  production state access, commit, push or editor-settings change was performed.
- No credential values were displayed or copied into artifacts. Google tools/SDK
  may use their existing credential caches; harnesses stored only status/counts.

## Discovered Gotchas & Caveats

- Working gcloud login and ADC are separate configurations; both worked here.
- One scraper is tied to one scrape/probe lifetime context. Create a fresh one
  after cancellation. SDK refresh calls are time-bounded; a shared acquisition
  may finish after an individual caller cancels.
- Google may return HTTP 400 for invalid API keys, so 400/401/403 are fatal rather
  than silently skipped. Raw credential, URL, header and response errors do not
  cross the public error boundary.
- DB integration build-tag tests and a long-running real token-expiry soak were
  not run. Refresh/concurrency/cancellation were covered offline.
- Go JSON test output capture was unsuitable for automated counting; a plain
  short suite was rerun and its actual package-level results were archived.
- Existing C3X G4/Flex/RTX/Hyperdisk mapping and unknown-price/region bugs remain.
  Successful OAuth access does not establish a trustworthy workstation estimate.
