## Decisions & Rationale

- Shared images outlive GPU VMs. A separate Terraform root under
  `src/terraform/registry/gcp/` creates the protected regional Docker repository
  with durable GCS state, optional existing CMEK and scoped publisher IAM.
- Workstation Terraform consumes an existing explicit repository, grants its
  attached dedicated service account reader access, and uses cloud-platform scopes.
  Repository project may differ from VM project. IAM API readiness is a project
  bootstrap prerequisite, not established by mocks or managed here.
- Optional YAML `artifact_registry` is disabled by default. Fields: `enabled`,
  `project`, regional `location`, `repository`, `images` workload-to-digest map.
  Reject mutable tags, mismatched repositories, invalid booleans and non-GCP use.
- `images.gr00t` selects the container service. Other images are pre-pulled only.
  This is not a full private-workstation mirroring implementation; models,
  datasets, database data, dirty source mounts and other services remain separate.
- Ansible authenticates root/systemd and the resolved SSH user with short-lived
  metadata tokens; no downloaded service-account key or cached plaintext token.
- Public examples remain generic. Personal profiles remain private and excluded
  from Git/build contexts; no personal configuration was copied into references.

## Discovered Gotchas & Caveats

- InventoryManager can decode JSON assigned in INI group variables into a dict;
  the role accepts both JSON text and an already-decoded mapping.
- Mutable default `create_tfvars({})` leaked registry settings between deployments;
  changed to an independent dictionary per invocation with a regression test.
- GCP root had not forwarded `security_profile` to its child module. Forwarding it
  now activates the existing enterprise dedicated-SA path. Opting into registry
  also changes the attached VM identity. A real apply may stop/update an existing
  VM; backup/secret/telemetry IAM is not inherited and must be scoped separately.
- Initial independent review found four blockers: metadata restore bypassed cloud
  validation; rejected initialization could overwrite metadata via destructor;
  root Docker configuration merge had a symlink-swap race; container-to-native
  GR00T selection did not stop/disable the old container. Cycle 1 fixed those
  paths. Re-review found a failed-concrete-constructor edge case (Alicloud after
  `super()`), resolved in cycle 2 by removing destructor autosave. Persistence is
  now explicit at validated workflow boundaries; GCP also saves resolved dynamic
  settings before external work. Registry tests now explicitly mock import-time
  public-IP/local gcloud project-default probes and deny unexpected external calls.
- User Docker configuration merges drop root and supplementary groups permanently
  before touching user-controlled paths. Inaccessible/root-owned user config
  fails closed; administrative ownership repair is a separate operation.
- No lint binaries/Black were available; do not claim those checks passed.
  Unit tests emitted TUI event-loop/resource-warning diagnostics; exit status was
  successful. Terraform formatting and Python compilation were checked separately.
- Baseline comparison found an unrelated fresh-checkout issue: `.gitignore:9`
  (`__*`) excludes the existing `src/tui/screens/__init__.py`. A detached HEAD
  worktree passed 91 tests but its TUI test failed importing `CloudAuthBridgeModal`.
  Copying only that untouched workspace initializer into the temporary checkout
  made the baseline TUI test pass, with two ResourceWarnings. No TUI or ignore-rule
  changes were made here. Future full-clean-checkout test work must address this
  missing tracked initializer rather than attributing it to the registry feature.
- Live IAM propagation, token identity, DNS/egress/VPC policies, CMEK availability,
  real registry pulls and Blackwell/GR00T workload health remain unverified.
