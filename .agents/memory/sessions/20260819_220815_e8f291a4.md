# Session Memory: DevContainer Git Auth Resolution & 4-Layer Defense-in-Depth

## Summary
Diagnosed and resolved the `fatal: could not read Username for 'https://github.com': terminal prompts disabled` error on `git push`. Implemented a 4-layer defense-in-depth credential resolution architecture across system gitconfig, lifecycle hooks, fast shell guards, and Docker named volume persistence.

## Decisions & Rationale
- **Diagnosed Root Cause**:
  - `gh auth setup-git` was previously only invoked in `postCreateCommand` via `setup.sh`.
  - In already-running containers or when VS Code connects/attaches, VS Code injects generic `[credential]` helpers routing to the desktop client IPC bridge. When terminal prompts are disabled or the host bridge is unresponsive, Git commands hang or error immediately.
- **Implemented 4-Layer Defense-in-Depth**:
  1. **Layer 1 (System Gitconfig)**: Configured `credential."https://github.com".helper` in `/etc/gitconfig` and `.devcontainer/Dockerfile`. Because it is URL-specific, it takes precedence over generic VS Code helpers across all subshells and users.
  2. **Layer 2 (Lifecycle Hooks)**: Added `postStartCommand` and `postAttachCommand` to `.devcontainer/devcontainer.json` to keep `~/.gitconfig` synchronized whenever VS Code attaches or starts.
  3. **Layer 3 (Zero-Latency Shell Guard)**: Added `<1ms` check to `/etc/bash.bashrc` and `/root/.bashrc` that auto-repairs git configuration if missing upon opening a shell without disk thrashing.
  4. **Layer 4 (Named Volume)**: Preserved GitHub CLI token persistence via `isaac-gh-config` volume.

## Discovered Gotchas & Caveats
- Git credential precedence treats URL-specific helpers (`[credential "https://github.com"]`) with higher priority than generic helpers (`[credential]`), successfully shielding Git from hanging on VS Code's host bridge.
