# Session Memory: Root Cause Resolution: PYTHONPATH Pollution of Base Python 3.14 by Omniverse cp312 Prebundle

## Summary
In this session, we identified the exact root cause of the `pydantic_core` error during `conda deactivate`:
1. **The Smoking Gun**:
   - `PYTHONPATH` was exported with `.../extscache/omni.kit.pip_archive...cp312/pip_prebundle`.
   - Omniverse Kit's prebundle contains `pydantic_core` compiled for **CPython 3.12** (`cp312`).
   - When `conda deactivate` ran, the base Conda executable (**Python 3.14**) searched `PYTHONPATH` first, attempted to load the `cp312` compiled `.so` extension, and failed with `No module named 'pydantic_core._pydantic_core'`.
2. **Resolution**:
   - Updated `deactivate.d/00_isaaclab_env.sh` in `lib/modules/conda.sh` to explicitly unset `PYTHONPATH`.
   - Confirmed that registering paths via `.pth` files (Pillar 3) eliminates this global shell pollution entirely.
