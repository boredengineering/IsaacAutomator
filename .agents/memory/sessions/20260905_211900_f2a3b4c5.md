# Session Memory: Terminal Visibility Diagnosis, VS Code WebGL GPU Glitch, and Strict Settings Guard

## Summary
The operator encountered a terminal issue where bash terminal text was completely invisible across VS Code unless manually highlighted or selected with the mouse. Diagnosed the root cause as Electron's shared WebGL terminal renderer (`xterm.js-webgl`) glitching, which drops text glyph rendering while the DOM selection overlay continues drawing. Resolved by disabling GPU acceleration (`"terminal.integrated.gpuAcceleration": "off"`). Codified a strict repository rule prohibiting agents from touching VS Code settings without explicit user permission.

## Root Cause Analysis
1. **Shared WebGL Canvas Context**: VS Code integrated terminals render via a shared WebGL GPU canvas context across all tabs. When this context desyncs or crashes (often triggered after heavy TUI full-screen redraws or Unicode palettes), the canvas stops painting text glyphs in all terminal tabs.
2. **The Selection Overlay**: The selection highlight is rendered via a separate HTML/DOM layer above the canvas. Selecting text forces the DOM layer to draw contrasting boxes over the glyphs, revealing the text only when highlighted.
3. **Remediation**: Setting `"terminal.integrated.gpuAcceleration": "off"` forces VS Code to use the standard, stable DOM canvas renderer.

## Strict Operator Constraint (Rule for All Future Agents)
> [!CAUTION]
> **NEVER EVER touch or modify VS Code settings (`.vscode/settings.json`, `/root/.vscode-server/data/Machine/settings.json`, User settings, or any IDE terminal/display configurations) without EXPLICIT user permission in the prompt.**
> 
> Agents must ask the user and receive confirmation before reading or editing any IDE configuration files.
