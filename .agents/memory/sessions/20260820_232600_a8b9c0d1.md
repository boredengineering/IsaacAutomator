# Session Memory: Automated Detection and Self-Healing of Mislocated Conda Environments and NVIDIA isaaclab.sh Integration

## Summary
In this session, we resolved the edge case where an orphaned system Conda environment (`/opt/conda/envs/isaaclab`) or missing named environment exists alongside a user's active `miniconda3`.
1. **Automated Drift Detection**:
   - `isaac-installer drift` detects `CONDA_ENV_MISLOCATED` and `CONDA_ENV_MISSING`.
2. **Automated Self-Healing**:
   - `isaac-installer repair` automatically purges orphaned `/opt/conda` directories, creates the native `isaaclab` named environment inside user's active `miniconda3`, and executes the official `./isaaclab.sh --install` within that healed environment.
3. **NVIDIA Docs Alignment**:
   - Analyzed official NVIDIA documentation regarding binary installations vs conda vs `./isaaclab.sh -p`. Confirmed that Isaac Lab's `isaaclab.sh` launcher natively routes to `$CONDA_PREFIX` when active, ensuring 100% compatibility across `python`, `isaaclab-env`, and `./isaaclab.sh -p`.
