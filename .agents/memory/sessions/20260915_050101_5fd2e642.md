# Session Memory: Bounded installer discovery, preview and naming implementation

## Summary

The user explicitly lifted the earlier implementation pause and requested parallel
agents, verification and reasoning through failures. Implemented and integrated
bounded offline slices, not the complete installer roadmap. Independent source
reviews and parent verification completed after regression-first fixes. Final
scoped run: **274 tests across 15 suites, all pass, no skips**.

## Delivered

- Exact case-preserving named workspace contract, collision refusal, pure path
  resolution, CLI > profile > defaults with provenance and no checkout adoption.
- `observe` for explicit workspace entry metadata, individual dist-info metadata
  and bounded Conda package records. No Git commands or robotics imports.
- Baseline/candidate/review JSON companions; accept/edit/reject/defer and decision
  retention across rescans, including reordered input sources. All are
  non-executable; actual candidate marker is `apply_supported: false`.
- Early no-change dispatch for admitted observation/preview, isolated system
  Python, Landlock + seccomp, complete inherited FD cleanup, credential/privilege
  checks, resource bounds and fail-closed unsupported modes.
- `install --dry-run` is explicitly incomplete profile-only stage/workspace
  intent, exit 2. It does not claim host conformance or known overwrite effects.
- Narrow cloud repository overrides: `--isaacsim-repo`, `--isaaclab-repo`,
  `--isaaclab-arena-repo`; selected repository/ref validation and matching Ansible
  transport. Official defaults remain; no Terraform URL leakage.
- README, usage guide, example workspace YAML and implementation register updated.

## Verification and fixes

Initial independent reviews caught real issues despite passing tests:

1. A high FD could survive after lowering RLIMIT_NOFILE. Fixed with checked
   `close_range(3, UINT_MAX)`, no bounded fallback; FD1000 regression returns EBADF.
2. Saved UID/GID, filesystem identities and capabilities could survive nominal
   non-root checks. These now fail before pinning/reading selected inputs.
3. Named repair/switch/sync paths bypassed the install-only gate. All named legacy
   dispatch is blocked; unknown commands refuse before legacy sources. Demos,
   Conda and audit now propagate named resolver failures before actions.
4. Discovery briefly diverged from the named resolver's character rules. It now
   preloads and calls the same pure validator; case/internal spaces survive while
   Unicode and unsupported punctuation are consistently refused.

Independent follow-up cleared sandbox security and named dispatch blockers. Final
narrow validator review PASS is in `/tmp/isaac-final-contract-review.json`.
Cloud transport review also passed. Final Python/shell syntax, whitespace, local
document links and added-production-source security pattern checks passed.

Parent regression suite counts: installer profile 24, workspace 17, discovery 22,
safe preview 17, discovery CLI 6, sandbox regressions 10, named safety 11, shared
profile 11, profile command 12, privacy 4, deploy command 44, fork transport 12,
deployer 57, artifact registry 18, distribution profile 9. Temporary per-suite
logs/results: `/tmp/isaac-profile-verification/`. These are not full-repository or
robotics runtime tests.

## Boundaries and remaining work

- No real workstation scan/install, backup/restore experiment, sync activation,
  VS Code settings change, container/cloud deployment, commit or push occurred.
- Named application remains blocked. Per-operation ownership, concurrency,
  preview freshness, tested recovery/cleanup and idempotent execution still need
  qualification before enabling it. Legacy ordinary installs remain unqualified.
- Actual local observation and user refinement are still P3/P4 gates. This
  devcontainer is not assumed to be the user's physical robotics workstation.
- Initial confinement is Linux x86_64, Landlock ABI >=5, seccomp; matching nonzero
  real/effective/saved/fs identities, zero capabilities and no supplementary groups
  beyond the primary group. Typical developer accounts may refuse. Never change
  memberships or weaken safety automatically to make a test pass.
- Directory grants include descendants; trusted observer code excludes private
  checkout contents, not Landlock independently within that admitted directory.
  YAML preview input still uses pathname reopen after size check; a bounded-FD
  parser is a recorded nonblocking integrity improvement before real usage.
- Candidate companions are not complete executable YAML; required unsupported
  tools/mappings remain visible. No blanket local/Ansible parity claim.
- Unicode names, active-checkout adoption, launcher target fidelity, full installer
  recovery/idempotence, continuous sync and devcontainer parity remain open.
- Full commit SHA reachability and explicit-ref network-error continuation retain
  existing limitations. Custom repository overrides on image-build commands
  refuse. No G4 GPU deployment qualification was added.
