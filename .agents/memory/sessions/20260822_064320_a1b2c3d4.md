# Session Memory: Ecosystem Conflict Traversal, PyTorch Split Analysis & Architectural Retrospective

## Summary
In this session, we conducted an in-depth code inspection of upstream `isaac-sim/IsaacLab-Arena`, `NVIDIA/Isaac-GR00T`, and their 4 external benchmark submodules (`LIBERO`, `SimplerEnv`, `robocasa`, `robocasa-gr1-tabletop-tasks`). We discovered and codified:
1. **PyTorch Version Divergence**:
   - `IsaacLab-Arena` strictly locks to `torch==2.11.0` (forced by Isaac Sim 6.0.0 wheels).
   - `Isaac-GR00T` strictly locks to `torch==2.9.0` (paired with `torchcodec==0.8.0` and `transformers==4.57.3`).
   - Confirmed why ZeroMQ microservice process separation on port 5555 is necessary to avoid binary symbol crashes.
2. **Dual-Directional Top-Down & Bottom-Up Conflict Matrix**: Added Section 5.6 to `isaac-install-plan.md` detailing every failure mode from user intent down to silicon, and low-level driver drift up to high-level benchmarks.
3. **Architectural Retrospective**: Added Section 5.7 to `isaac-install-plan.md` reviewing how NVIDIA engineered solutions (Composable Triplet Architecture, Relative EEF action spaces, Cosmos-Reason2-2B native aspect ratio VLM) and how IsaacAutomator engineered solutions (ZeroMQ process boundary, editable bridge, dual-remote push guards, headless virtual EDID, self-healing state ledger).
