# Session Memory: Direct Conda Provisioning Subcommand & envs_dirs Registration

## Summary
In this session, we addressed why `conda activate isaaclab` reported `EnvironmentNameNotFound`:
1. **Cause**: In the previous run, the `repair` command was in the middle of reconciling item 1 (`IsaacLab` clone) when `conda activate isaaclab` was invoked before item 3 (`CondaEnv` creation) had completed.
2. **Direct Subcommand**: Made it possible to directly provision only the Python runtime via `./bin/isaac-installer install --only python` in ~30 seconds.
3. **envs_dirs Registration**: Ensured `conda config --append envs_dirs` runs during `install_python_env` so named activation is recognized immediately by the user's active miniconda.
