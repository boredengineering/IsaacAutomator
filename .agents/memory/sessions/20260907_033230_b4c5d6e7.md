# Session Memory: Architectural Comparison & Native Cloud Ansible Replication Plan: Isaac Installer into Ansible

## Summary
Conducted an exhaustive technical comparison between `isaac-installer` and `src/ansible/`, confirming that Ansible is significantly behind in robotics runtime environments, foundation models, complete Arena linking, dual-remote fork workflows, and self-healing. Authored the comprehensive architectural reference and 5-phase native replication plan at `.agents/references/plans/isaac-installer-ansible-compat.md` to replicate `isaac-installer` directly into idiomatic, native Ansible roles, leveraging Ansible's unique cloud superpowers (Packer golden image baking, agentless SSH/IAP execution, declarative idempotency, and lifecycle tagging).

## Key Findings & Comparative Diagnostics
1. **Python Runtime**: Ansible runs `./isaaclab.sh --install` against Isaac Sim's internal pre-bundled Python without environment isolation. In contrast, `isaac-installer` provides a hybrid named Conda (`isaaclab`) + UV acceleration architecture, `/usr/local/bin/isaaclab-env` CLI shim, scoped activation hooks, dynamic Vulkan manifest resolution, and CP312 isolation.
2. **IsaacLab-Arena**: Ansible executes `git clone --recurse-submodules` and halts (unlinked, uninstalled). `isaac-installer` provides 935 lines of automation for detached HEAD checkout, submodule clean sync, editable pip install into Conda & Sim, Pinocchio/Pink WBC integration, and evaluation test runners.
3. **Physical AI Foundation Models**: Ansible has zero support for Vision-Language-Action (VLA) models. `isaac-installer` deploys the full NVIDIA Isaac-GR00T Foundation Model Stack (`gr00t.sh`: DiT 1.09B + Cosmos-Reason2-2B, ZeroMQ IPC server, weights pre-caching, mock mode) and LeRobot.
4. **Git Topologies**: Ansible uses shallow flat clones. `isaac-installer` implements a Dual-Remote Git Topology (`origin` fork / `upstream` official) with branch pushRemote protection and auto-registration in GitHub Desktop GUI.
5. **Hardware & Self-Healing**: Ansible has basic driver tasks, whereas `isaac-installer` detects Blackwell/Ada architectures, NVMe SMART health, configures 1ms FTDI serial kernel latency rules, and maintains a structured JSON state ledger (`state.json`) with automated drift self-healing (`repair`).
6. **Ansible Cloud Strengths**: Packer image baking (reducing launch times from 45m to 3m), agentless SSH/IAP execution, headless X11 virtual displays, dynamic GPU Bus ID remapping for AMIs, multi-protocol streaming for DCV/NoMachine/KasmVNC, Spot preemption listeners, GCS/S3 sync timers.

## Native Ansible Replication Plan (5 Phases)
- **Phase 1: Core Foundation & Modern Runtime**: Implement `roles/conda` (Miniconda3, named `isaaclab` env, `uv`, `isaaclab-env` CLI shim, Vulkan ICD hooks), `roles/auth` (hardware groups, git identity, HF/NGC/WandB tokens), and `roles/system` (NVMe tools, cloud CLIs).
- **Phase 2: Sim Engine & Modern Isaac Lab**: Update `roles/isaacsim-source` (multi-version layout, atomic symlink swapping, setup_conda_env compatibility bridge) and `roles/isaaclab-source` (Conda install via `./isaaclab.sh --conda`, dual-remote topology, GitHub Desktop registration).
- **Phase 3: IsaacLab-Arena Pipeline & Teleoperation**: Update `roles/isaaclab-arena-source` (submodule clean sync, `isaaclab-env pip install -e .`, Pinocchio/Pink WBC dependencies) and implement `roles/hardware-teleop` (1ms FTDI udev rule, SpaceMouse daemon).
- **Phase 4: Foundation Models & Physical AI**: Implement `roles/gr00t` (DiT + Cosmos-Reason2, ZeroMQ systemd server on 5555, weights cache), `roles/lerobot` (teleop calibration), and update `roles/demos`.
- **Phase 5: State Ledger, Golden Image Baking & Lifecycle Verification**: Implement `roles/state-ledger` (`.isaac-state.json`, `tags: __verify`, boot self-healing in `autorun.yml`), validate Packer image baking (`image-gcp`, `image-aws`), and run end-to-end dry-run tests.
