# Session Memory: Hybrid Conda + UV Architecture Plan & Rationale

## Summary
In this session, we formalized and documented the **Hybrid Conda Named Environment (`conda activate isaaclab`) + UV Pip Acceleration Model** inside [`isaac-install-plan.md`](file:///workspaces/IsaacAutomator/.agents/references/docs/isaac-install-plan.md) (Section 3).

## Key Architectural Points Planned & Documented
1. **Standalone Engine vs Pip Package Rationale**:
   - Analyzed why `pip install isaacsim` fails in production (ABI crashes, missing native assets, Vulkan shader compilation stutters) and confirmed the Standalone Engine + POSIX `_isaac_sim` symlink as the chosen foundation.
2. **Conda vs. UV Trade-offs**:
   - Addressed developer ergonomics: Conda provides central named environments (`conda activate isaaclab`) discoverable globally and auto-detected by IDEs. UV provides sub-second package resolution without slow solver waits.
3. **The Hybrid Solution Architecture**:
   - Environment Provisioning: `conda create -y -n isaaclab python=3.10` (or `3.12`).
   - Acceleration: `uv pip install --python "$CONDA_PREFIX/bin/python"` for PyTorch, extensions, and downstream dependencies.
   - Topological editable extension linking (`uv pip install -e .`).
4. **Shell Cleanliness & Activation Hook Guarantee**:
   - Zero `.bashrc` pollution: Omniverse runtime variables (`EXP_PATH`, `CARB_APP_PATH`, `VK_ICD_FILENAMES`) are scoped strictly to `$CONDA_PREFIX/etc/conda/activate.d/00_isaaclab_env.sh` and unset upon `conda deactivate`.
5. **Developer Interaction Modalities**:
   - Interactive terminal, zero-activation CLI shim (`isaaclab-env`), bundled sim runner (`./isaaclab.sh -p`), and IDE direct interpreter selection.
6. **Pre-Implementation Verification Gates**:
   - Established discovery, environment creation, tensor verification, shell isolation, and hook restoration gates.
